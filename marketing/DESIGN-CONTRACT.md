# shifts-ai.store — build contract (v2 rebuild)

Owned source for the customer-facing landing page. Everything here is binding for every file under `marketing/site/`.
Reviews that drive this contract: the three-review dossier (Claude brainstorm, Codex, Kimi K3), 2026-09-10.

## Non-negotiables
- Static files only (Firebase Hosting). No backend, no API keys, no analytics until the owner supplies IDs, no external scripts. Fonts: Google Fonts **Cairo only** (weights 400/600/700/800). Icons: inline SVG (Lucide-style, stroke 2, 24 viewBox) from `assets/js/core.js` `SHIFT.icon(name)`.
- Weight budget: whole page (html+css+js, gzipped) **≤ 120 KB**. No libraries, no images except inline SVG.
- Arabic-first RTL; English is a toggle. Mobile-first (design at 360×640 first, then ≥768, ≥1024).
- Honesty: every simulation carries a small visible label «مثال توضيحي» / "Illustrative example". No fake counters, no fake testimonials, no "X businesses" numbers unless the owner supplies them (none supplied yet → no numbers).
- WhatsApp: number constant `SHIFT.WA = "962776788972"` (owner has NOT confirmed it yet — keep it in one place). Every CTA opens `https://wa.me/${WA}?text=${encodeURIComponent(msg)}` where `msg` comes from `SHIFT.composeMessage()`.

## Files (vanilla, no build step)
```
marketing/site/index.html              shell: <head>, nav, section mount points in the fixed order below, footer, sticky bar, script tags in order
marketing/site/assets/app.css          the ONLY stylesheet SHIPPED — generated by `node marketing/tools/build-css.js` from assets/css/tokens.css + assets/css/base.css + assets/css/sections/<name>.css (one per section; builders own their own file)
marketing/site/assets/js/content.js    window.SHIFT_CONTENT = { ar:{...}, en:{...}, products:[...], cases:[...], ... } (bilingual data, no DOM code)
marketing/site/assets/js/core.js       window.SHIFT = { state, t(), setLang(), icon(), composeMessage(), clock(), fmtNum(), on(), sections:{} , mount() }
marketing/site/assets/js/sections/<name>.js   each file: SHIFT.sections.<name> = { id, render(el), init(el) }  — pure DOM strings + event wiring; NO CSS in JS
marketing/site/assets/css/sections/<name>.css   styles for that section only, all selectors scoped under `#<id>` (or `.sticky` / `.nav`)
marketing/tools/build-css.js             concatenates css → assets/app.css (tokens, base, then sections in page order)
marketing/tools/check-consistency.js     the sector-consistency + arithmetic gate (node, uses jsdom-free DOM via string checks or Playwright when available)
marketing/tools/size.js                  prints gzipped size of html+css+js and fails above 120 KB
```
Load order in index.html: content.js → core.js → sections/*.js (any order) → inline `SHIFT.mount()` at the end of body. Each section renders into `<section id="…" data-section="…">` that already exists in index.html.

## Phone (`#karam`, component `phone`)
- Status bar with the **visitor's real time**; chat header with avatar (first letter, gold circle) + business name (default per sector, e.g. «عيادة د. رنا») + label «حساب أعمال» (no blue tick) + ✏️; tapping the name turns it into `<input maxlength=28 enterkeyhint="done">`, saved to `localStorage['kb-name']`; the first bubble re-renders with the name (typing 600ms then swap), no full restart.
- Script chosen by `sector` × **time of day**: closed (night) / before-open (morning) / open (peak); Friday variant for clinic/salon/realestate; Ramadan variant for restaurant via `Intl.DateTimeFormat('en-u-ca-islamic-umalqura',{month:'numeric'})` in try/catch. Opening hours per sector: clinic 9–21, restaurant 12–24, store 10–22 (support hours; orders arrive 24/7). Friday variant for clinic; Ramadan variant for restaurant; a 'promo night' variant for store (orders spike after 9 pm).
- Timing: customer bubble immediate; Karam: typing indicator 500–700ms then bubble 200ms (`opacity + translateY(4px)`, no scale). Each bubble's timestamp = real time when it appeared. One cycle, then a quiet «▶ أعد التشغيل» link. Bubble sides follow the sender (customer start / Karam end) independent of page direction.
- A caption under the phone: «الردود هنا محاكاة تعمل داخل متصفحك. كرم الحقيقي يتدرّب على أسعارك ومواعيدك.» And an honest night line above the CTA: «الآن الساعة 11:42 م — فريقك نايم. اترك رسالتك، ونتواصل معك الصباح.» (never promise an instant human reply at night).

## State & message composer (`core.js`)
`SHIFT.state = { lang:'ar', sector:null, bizName:'', bundle:[], roi:{...defaults}, need:[] }` persisted to `localStorage['kb-state']` (30-day expiry). `?b=clinic|restaurant|store` in the URL sets `sector` (wins over storage) and is removed with `history.replaceState`. `SHIFT.composeMessage()` builds ≤ 700 chars in the current language from the fields that exist, e.g. «مرحبًا شِفت 👋 عندي عيادة د. رنا. يهمّني: كرم بوت + الحجوزات. عندي ~120 رسالة/يوم وأخسر ~850 دينار/شهر حسب الحاسبة. متى نحكي؟».

- **Gold appears in exactly three places**: ROI result number, flagship badge/border on the Karam card, current step marker. Nowhere else (no gold headline chips, no gold dividers, no gold seals).
- **Green `--wa` appears only on WhatsApp CTAs** (opening CTA, nav circle, sticky bar, contact CTA, per-product «اسأل عن»). Electric = internal interaction (tabs, selected chips, links). Ink = structure (nav text, ops panel, phone frame).
- Type: Cairo. Body 16px/1.7; small 14px/1.6; labels 13px/1.5 min; H1 30px (≥768: 44px); H2 26px (≥768: 34px); H3 18px; all headings line-height 1.45, `letter-spacing:0`, `text-wrap:balance`. Numbers: Latin digits everywhere, `font-variant-numeric: tabular-nums`, `<bdi>` around Latin terms (WhatsApp, ERP, SHIFT, Excel).
- Spacing: sections `padding-block:48px` (≥768: 88px); section head → content 24px; card padding 16–20px; radii `--r` for cards, `--r-lg` for the phone/ops panels; one shadow (`--shadow`) only on the ops panel, the phone, and the ROI result.
- Motion: only `opacity`/`transform`; durations ≤ 240ms except the phone's typing rhythm; no infinite animations; hover effects only inside `@media (hover:hover)`; `:active{transform:scale(.98)}` on buttons; full `@media (prefers-reduced-motion: reduce)` opt-out; no JS timers running while a section is off-screen (IntersectionObserver).
- Dark mode: not required (the site commits to a light ground) — but paint every color explicitly.

## Accessibility & RTL
Touch targets ≥ 44px; visible `:focus-visible` (2px electric outline); tabs/accordion with proper `role`/`aria-selected`/`aria-expanded`; `scroll-margin-top:64px` on all sections; `lang`/`dir` on `<html>` switch with the language toggle; `dir="auto"` on text inputs; form inputs `font-size:16px` (no iOS zoom).

## Copy rules (Arabic)
Modern Standard with light Jordanian warmth in chat bubbles («تمام، حجزتلك…»). Write from the owner's side: what he sees, what reaches him. Avoid: «بدلًا منك» (→ «عنك، وبقواعدك»), «صندوق أسود», numeric promises («60 ثانية»), «مباشر/Live» on anything simulated. English strings are a faithful, natural translation, not literal.

## Sector consistency — single source of truth (added after owner feedback, 2026-09-10)
The current page showed sector «مركز أطفال» selected while the loyalty card read «كافيه زيتون · وجبة مجانية». That is a defect class, not a typo. Rules:
- `content.js` defines ONE `SHIFT_CONTENT.sectors` table keyed by **`clinic | restaurant | store`** (nothing else). Each entry holds, bilingually: `label`, `exampleName` (clinic «عيادة د. رنا», restaurant «كافيه زيتون», store «متجر النور»), `unit` (clinic موعد / restaurant طلب / store طلب), `unitPlural`, `reward` (clinic «جلسة تنظيف مجانية», restaurant «وجبة مجانية», store «شحن مجاني على الطلب القادم»), `avgTicketJOD`, `pointsPerJOD`, `rewardAt`, `hours {open, close}`, `staffRoles` (clinic: استقبال/ممرضة; restaurant: كاشير/مطبخ/توصيل; store: خدمة عملاء/تغليف/توصيل), `opsRows[]`, `chat{night,morning,peak,friday?,ramadan?,promo?}`, `cases{problem, karam, result}`, `faq[]`, `roiDefaults{msgsPerDay, avgTicketJOD, missedRate, replyMinutes}`.
- Store sector content is NEW (not in the old page) — author it to the same depth as clinic/restaurant: order status, product availability & sizes, COD confirmation, delivery tracking, returns/exchanges, abandoned-cart follow-up, and a 'promo night' script.
- **Every** demo (ops card, phone, loyalty, attendance, ROI defaults, builder, contact prefill, composed WhatsApp message) reads from `SHIFT_CONTENT.sectors[SHIFT.state.sector]`. No demo may hard-code a business name, unit, reward, or price.
- Changing the sector anywhere re-renders every sector-aware component immediately (single `SHIFT.on('sector', fn)` event).
- The loyalty message must be arithmetically exact from the visible rules: `points = round(avgTicket × pointsPerJOD)`, `remaining = max(0, rewardAt − balance)`, and the text names the sector's reward. The card's business name = `state.bizName || sector.exampleName`.
- QA gate (automated, in `marketing/tools/check-consistency.js`): for each sector, render every sector-aware component and assert no string from another sector's `exampleName`/`reward`/`unit` appears; assert loyalty/ROI arithmetic against the displayed inputs. The build is not deployable while this check fails.

|---|---|---|---|---|---|---|
